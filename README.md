# WaitWise 使用与搭建说明

## GitHub Pages 上传版

将本文件夹内的所有文件直接上传到 GitHub repository 根目录，然后进入 `Settings → Pages`，选择 `Deploy from a branch → main → /(root)`。发布后：

- 乘客页面：repository 对应的 GitHub Pages 根链接。
- 测试员页面：在根链接后加 `facilitator.html`。
- 不要只上传 ZIP；GitHub repository 中必须直接看到 `index.html`。


这是配合纸板公交站公共屏使用的课堂低保真交互原型。公交时间、可信度、乘客请求和方案反馈均为模拟内容。该原型形式仍需提前与 tutor 讨论。

## 打开屏幕

- 在线版：打开交付的站点链接。新站点保持本人私有，需要同一账号的访问权限；这不代表组员可以直接用自己的账号打开。
- 测试员页面：在在线链接后加 `?mode=facilitator`。所有控制仅影响同一浏览器；不能从另一台设备远程控制平板。
- 离线版：解压交付包，用桌面电脑的 Chrome / Edge / Safari 打开 `WaitWise_Offline.html`。默认是乘客屏幕。
- 离线测试员页面：直接打开交付包里的 `WaitWise_Facilitator.html`。在线也可在站点链接后加 `/facilitator.html`。手机/平板文件预览器可能不执行 JavaScript；这时请使用在线版。
- 独立离线 HTML 不依赖外部字体、图片、脚本、API 或安装步骤。网络不可用时，桌面浏览器仍可运行。

## 课堂测试流程

1. 在测试员页面的 Test controls 选择场景，选择各功能的 A / B / C 展示方式。
2. 点击 Open passenger view，把同一台设备交给参与者。底部 Test controls 返回控制页。
3. 用户通过四个核心入口操作：ETA Range、Confidence、Passenger Requests、Decision Support。Waiting Guide 是截图中提到的第五个辅助功能，可关闭。
4. 需要模拟更新时，由测试员接过设备，回控制页改变场景后返回乘客页。也可在同一浏览器另开控制页，利用本地消息同步；不要假定跨设备同步。
5. 完成测试后，点击 End session 清空乘客选择并回首页。此操作保留测试场景与展示方式。
6. Observations 中填真实观察。离开或刷新前导出 JSON；记录仅在当前页面内存中。它不能替代规定的视频。

## 四个核心功能

- ETA：展示公交到当前站点的预计时间范围，不是保证的最大等待时间。
- Confidence：High / Low 描述到站预测的可靠性，不代表座位、空间或安全性。没有真实概率计算。
- Passenger Requests：轮椅空间、优先座位、车上宠物信息；选择、确认、反馈。预期接收方为运营方乘客支持团队，原型不发送真实请求，也不承诺有空位或没有宠物。
- Decision Support：比较等 412、步行、步行到其他站乘 422。计算等候＋乘车／步行的总行程时间，可设置 5–180 分钟到达期限，选择方案并看到结果。

## 场景与三种展示方式

- Stable：3–5 分钟，High。
- Uncertain：6–12 分钟，Low。
- Delayed：15–25 分钟，Low。
- 补充数字比较场景：4–9 分钟、2–10 分钟，均为 Low。
- ETA 的三个版本使用完全相同的时间、可信度和说明，只改变时间可视化：A = 横向三点时间轴，B = 横向高亮区间，C = 纵向标注时间轴。Compare concepts 可将三种格式并排展示并记录偏好。
- Confidence 的三个版本使用完全相同的可信度标签与解释，只改变可视化：A = 分段状态条，B = 横向标注刻度，C = 定性仪表盘。Compare concepts 可并排展示并单独记录偏好。
- Passenger Requests 固定使用完整列表版本，包括请求说明、确认步骤、结果反馈和“不保证可用”的限制说明，不再进行 A / B / C 对比。
- Decision Support 与 Waiting Guide 仍可在 Test controls 中切换展示方式，但不加入核心并排比较。
- 同时改变数字和版式会干扰对“版式偏好”的解释，因此数字比较与格式比较分开进行。

## 纸板模型

建议背板约 45 cm 宽、60 cm 高，按实际平板调整。准备底板、两块三角支撑、胶带、剪刀／美工刀和打印材料。平板放独立稳固支架；纸板不负责承重。模型无需整座真实公交亭。

`WaitWise_Print_Kit.pdf` 提供 A4 标识、五个测试任务、英文主持稿和空白观察表。在线的 Build & submit 也能打印标识和表格。图中 WAITWISE、大标题、站牌由这些材料实现；屏幕使用本原型。

在允许的区域用可移除纸胶带模拟等候区。测试发现屏幕、看懂信息、提交请求和作决定的整体过程。纸板外框本身不能保证符合“不得只做独立 App / 网站”的课程要求。

## 五人分工与提交

原始制作者交接；一人优化原型；两人负责纸板结构与标识／场景；一人负责测试计划、稿件、材料和整合。五个人各自至少主持并记录一场完整测试，提供自己的真实数据、签署同意书和个人章节；每人参加其他组的测试并记录该组 tutorial、组名、原型名。

测试至少五个任务，全程英文。先取得课程同意书后录像；本原型的 draft consent checklist 仅为工作草稿，不能代替课程要求的官方表格。SUS 如果使用，请用课程模板。

Part C 包含小组封面、测试计划、五个个人章节、每人完整测试视频及 AI appendix。AI appendix 记录实际 AI 用途、提示、人工检查与修改。原型和模板不代表已经进行过测试；不要填写虚构结果。

## 验证范围

已用模拟 DOM 检查五个场景、五个功能、三种展示方式、请求确认、出行总时间、状态更新、重置与打印视图。未执行真实浏览器视觉 QA，测试前请在实际平板上试点全部任务。
